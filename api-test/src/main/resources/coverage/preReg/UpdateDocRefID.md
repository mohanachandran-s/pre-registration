**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Updates the external reference number stored against a single already-uploaded document — a free-text field the registration centre can use to cross-reference the document against their own paper/physical filing, separate from the document's internal system ID.

**Request & response**

No request body — `documentId` is a path parameter, `preRegistrationId` and `refNumber` are query parameters:
```
PUT /preregistration/v1/documents/document/{documentId}?preRegistrationId={preRegistrationId}&refNumber={refNumber}
```
On success, `response` is the literal string `"STATUS_UPDATED_SUCESSFULLY"` (note the product's own spelling). On failure, `errors[0].errorCode` identifies the problem — see Technical details for the real codes this endpoint actually throws.

**Who can call it**

The applicant themselves, or registration-centre staff (an officer, supervisor, or admin), may update a document's reference number — broader than most document-mutation endpoints in this module, which are typically restricted to the applicant alone. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
