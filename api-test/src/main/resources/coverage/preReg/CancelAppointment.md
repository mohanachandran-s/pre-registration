**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Used to cancel a booked appointment for a pre-registration application, freeing the reserved slot and reverting the application's status. This path is served by the separately deployed booking service, not by the code in this repo (see Technical details).

**Request & response**

No request body — `preRegistrationId` is a path parameter. This subject's YAML uses:
```
PUT /preregistration/v1/appointment/{preRegistrationId}
```
On success, no distinct fields are asserted by any current case (`checkErrorsOnlyInResponse: true`). On failure, `errors[0].errorCode` = `PRG_APP_013` (application not found) or `PRG_BOOK_RCI_013` (nothing valid to cancel — already canceled, never booked, or in an incompatible state).

**Who can call it**

Intended to be the applicant themselves, a registration-centre officer, or a pre-registration admin, based on the equivalent role rule documented for `CancelApplicationsAppointment.md`'s confirmed-correct endpoint. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_

**Correction (2026-10-22): the `/preregistration/v1/appointment/...` path is most likely right — it is the separately deployed booking service's API.** The application service itself calls exactly these URLs (`appointment.book.url`, `appointment.getavailablity.url`, `appointment.multi.book.url` in `pre-registration-application-service/src/main/resources/application.properties`); the booking service's code was removed from this repository (commit `64048f144e`, "Develop 1.1.2 (#95)"), which is why no controller here matches. Its `PRG_BOOK_RCI_*` error codes come from that service too, so they can't be verified against this repository's source.
