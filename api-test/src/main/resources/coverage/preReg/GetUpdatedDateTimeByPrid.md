**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Given a batch of `preRegistrationId`s, returns each one's last-updated timestamp in a single call — a bulk lookup used by registration-centre client software to detect which locally-cached applications have changed since it last synced, without fetching each one's full record individually.

**Request & response**

```json
{
  "id": "mosip.pre-registration.demographic.retrieve.date",
  "version": "1.0",
  "requesttime": "2026-08-07T10:00:00.000Z",
  "registartion_center_id": "10003",
  "pre_registration_ids": [
    { "pre_registration_id": "98745627893456" },
    { "pre_registration_id": "12345678901234" }
  ]
}
```
On success, the response is a map from each ID to its update timestamp:
```json
{
  "response": {
    "98745627893456": "2026-08-07T10:00:00.000",
    "12345678901234": "2026-08-06T09:30:00.000"
  },
  "errors": null
}
```
If any ID in the list doesn't correspond to a stored record, `errors[0].errorCode` = `PRG_PAM_APP_005` for the whole call (it's an all-or-nothing lookup, not a partial result).

**Who can call it**

Registration-centre officers, supervisors, admins, or the registration-processing role may call this — and unlike some sibling endpoints, a plain applicant (`INDIVIDUAL`) is also allowed. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_

<summary>Technical details (automation + verification notes)</summary>

**Where the role rule lives:** `@PreAuthorize("hasAnyRole(@authorizedRoles.getPostapplicationsupdatedtime())")` on `DemographicController.getUpdatedDateTimeByPreIds`; roles configured via `mosip.role.prereg.postapplicationsupdatedtime` = `REGISTRATION_OFFICER, INDIVIDUAL, REGISTRATION_SUPERVISOR, REGISTRATION_ADMIN, REGISTRATION_PROCESSOR`. Verified against the live controller source.

**All-or-nothing lookup, confirmed against `DemographicService.getUpdatedDateTimeForPreIds`:** the method queries `demographicRepository.findByStatusCodeInAndPreRegistrationIdIn(...)` for the whole list at once and throws `RecordNotFoundForPreIdsException(PRG_PAM_APP_005)` if the result set comes back empty — it doesn't return a partial map with only the IDs it found. An empty/null `pre_registration_ids` list is a separate branch entirely, throwing `PRG_CORE_REQ_001` before the repository is even queried — that's the gap the `validation` placeholder row above targets.

**Despite the field being called `POST`, this is functionally a read.** `restMethod: post` in the YAML correctly matches the wired `SimplePost` script class — no mismatch here, unlike the one found in `UpdatePreRegStatus.md`. `POST` is used because the request needs a body (a list of IDs), not because it mutates anything.
