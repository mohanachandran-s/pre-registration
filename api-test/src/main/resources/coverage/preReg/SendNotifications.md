**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Triggers an SMS/email notification to an applicant — typically used to confirm a booked appointment (name, registration centre, appointment date/time) after `bookAppointment`/`bookAppointmentByPRID` succeeds. Two real, distinct endpoints exist for this: `/notification/notify` (always sends as a single, non-batch notification) and `/notification` (the batch/internal-style variant, `isBatch=true` internally) — both are genuine, separate `@PostMapping`s on the same controller, not a YAML wrong-endpoint bug like the ones found in batch 5.

**Request & response**

Multipart form data — a JSON part plus an optional file attachment:
```
POST /preregistration/v1/notification/notify
Content-Type: multipart/form-data

NotificationRequestDTO: {
  "id": "mosip.pre-registration.notification.notify",
  "version": "1.0",
  "requesttime": "2026-08-11T10:00:00.000Z",
  "request": {
    "name": "Test Applicant",
    "preRegistrationId": "98745627893456",
    "appointmentDate": "2026-08-20",
    "appointmentTime": "09:00:00",
    "mobNum": "9090872333",
    "emailID": "applicant@example.com",
    "isBatch": true
  }
}
langCode: eng
```
On success, no distinct fields are asserted by any current test (`checkErrorsOnlyInResponse: true`). On failure, `errors[0].errorCode` = `PRG_PAM_CORE_001` (unrecognized `id`) or `PRG_PAM_APP_005` (application not found).

**Who can call it**

For `/notification/notify`: the applicant themselves, a registration-centre officer, or a pre-registration admin. For `/notification`: only the applicant or a pre-registration admin — narrower, no `REGISTRATION_OFFICER`. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_

**A third, internal-only mapping exists:** `POST /internal/notification` (`sendNotificationsInternal`) — same role property as `/notification`, documented for use by the batch job. No YAML in this module targets it, which is expected — not part of the public API surface this coverage matrix tracks (same pattern as `AppointmentController`'s internal cancel mapping, see `CancelApplicationsAppointment.md`).
