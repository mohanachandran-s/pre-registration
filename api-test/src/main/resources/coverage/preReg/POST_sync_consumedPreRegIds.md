**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Lets the registration processor tell pre-registration which applications have been consumed (turned into registrations), so they can be archived and no longer changed.

**Request & response**

The standard envelope with a `ReverseDataSyncRequestDTO` holding the list of consumed `preRegistrationIds`. The response reports how many were stored.

**Who can call it**

Registration staff and the registration processor (`REGISTRATION_OFFICER, REGISTRATION_SUPERVISOR, REGISTRATION_ADMIN, REGISTRATION_PROCESSOR`); anyone else gets HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
