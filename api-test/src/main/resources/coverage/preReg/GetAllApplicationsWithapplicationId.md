**About this endpoint**

**What this endpoint does**

Identical purpose and identical controller method to `GetApplicationWithPrId.md` — fetches the application-tracking record (booking type, status, appointment slot) by ID. This subject and that one document the same real endpoint under two different YAML-driven names; between the two, this subject carries the module's only automated positive-case coverage for it.

**Request & response**

No request body — `applicationId` is a path parameter:
```
GET /preregistration/v1/applications/{applicationId}
```
On success:
```json
{
  "response": {
    "applicationId": "98745627893456",
    "bookingType": "NEW_PREREGISTRATION",
    "applicationStatusCode": "Application_Incomplete",
    "bookingStatusCode": null
  },
  "errors": null
}
```
On failure (ID not found), `errors[0].errorCode` = `PRG_APP_013`.

**Who can call it**

Only a registration-centre officer or the applicant themselves may fetch an application by ID. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
