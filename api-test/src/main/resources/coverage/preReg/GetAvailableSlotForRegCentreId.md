**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Used to list the open appointment slots (dates and time windows) available at a given registration centre — this is exactly what `bookAppointment.md`'s automation calls live before every booking to discover a real slot to book. This path is served by the separately deployed booking service, not by the code in this repo (see Technical details); `FetchAvailabilityData.md` documents the confirmed-correct version.

**Request & response**

No request body — `registrationCenterId` is a path parameter. This subject's YAML uses:
```
GET /preregistration/v1/appointment/availability/{registrationCenterId}
```
On success, the response lists the centre's open slots (see `FetchAvailabilityData.md` for the fuller documented shape, since that subject's endpoint is the one confirmed to exist). On failure, `errors[0].errorCode` = `KER-MSD-215` for an unrecognized registration centre.

**Who can call it**

Intended to be the applicant themselves, or a registration-centre officer, based on the equivalent role rule documented on `FetchAvailabilityData.md`. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
