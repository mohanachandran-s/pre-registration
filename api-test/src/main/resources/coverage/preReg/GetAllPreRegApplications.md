**What this endpoint does**

Same real endpoint as `GetAllApplications.md`'s no-`type` unit — lists every application the logged-in user owns. See that file for the full request/response contract and role documentation; this subject exists as a separate set of scenarios (baseline, "with lost-UIN applications present", "with a deleted application present") over the identical `GET /applications` call.

**Request & response**

See `GetAllApplications.md` — identical call shape (`GET /preregistration/v1/applications`, no request body) and identical response envelope (`response.allApplications[]`).

**Who can call it**

See `GetAllApplications.md`'s "Who can call it" — same controller method, same role list. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_

If this module wants real coverage of those two scenarios, the cases would need to reference a specific application (e.g. via `$ID:AddLostUinApplication_..._applicationId$` / `$ID:DeletePreRegistration_..._preRegistrationId$`) and assert on the returned list's contents rather than just the absence of `errors`.
