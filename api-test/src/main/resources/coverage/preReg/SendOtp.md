**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Sends a one-time password to a user's phone or email, as the first step of the login flow that ultimately issues the `Authorization` cookie every other endpoint in this module relies on (see `ValidateOtp.md`, which redeems the OTP this endpoint sends). The same `userId` field accepts either a phone number or an email address — the server auto-detects which channel to use based on the value's format.

**Request & response**

```
POST /preregistration/v1/login/sendOtp/langcode
{
  "id": "mosip.pre-registration.login.sendotp",
  "version": "1.0",
  "requesttime": "2026-08-11T10:00:00.000Z",
  "request": { "userId": "user@example.com", "langCode": "eng" }
}
```
On success, `response.status` = `"success"`. On failure, `errors[0].errorCode` = `PRG_PAM_LGN_008` if `userId` isn't a valid-looking phone number or email.

**Who can call it**

Unauthenticated — this is a pre-login endpoint, part of how a caller obtains credentials in the first place, so it doesn't sit behind the same cookie-based authorization every other endpoint in this module does. _(See `README.md`'s "How authentication works in this module" for how the credential this flow produces is used elsewhere.)_

<details>
<summary>Technical details (automation + verification notes)</summary>

**Where the validation logic lives:** `LoginController.sendOTPWithLangCode` → `LoginCommonUtil.validateUserId`, which null/empty-checks `userId` and then tries `validationUtil.phoneValidator(userId)` then `validationUtil.emailValidator(userId)`; anything matching neither throws `InvalidRequestException(LoginErrorCodes.PRG_AUTH_008.getCode(), ...)`. `PRG_AUTH_008.getCode()` returns `"PRG_PAM_LGN_008"` — the enum name and its `.getCode()` value diverge here too, but every throw site in `LoginCommonUtil` correctly calls `.getCode()`, so (unlike the `PRG_CORE_REQ_001`-`_012` fragility documented on `createPrereg.md`) there's no refactor-risk here — verified by reading all three throw sites directly.

**A separate, deprecated sibling endpoint exists:** `LoginController.sendOTP` (`POST /login/sendOtp`, no `/langcode`) is `@Deprecated(since = "1.2.0", forRemoval = true)` and gated behind `mosip.preregistration.sendotp.allowapi` (defaults to `false`) — if that flag is off, it throws a `DeprecatedException` regardless of input. This subject's YAML correctly targets the non-deprecated `/langcode` variant; not a concern for any current case.
