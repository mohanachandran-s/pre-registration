**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Fetches the full demographic identity record for a pre-registration application — name, address, date of birth, contact details, and any other identity fields captured by `createPrereg`/`UpdatePreregistration`. This is the "read the identity data back" counterpart to those two write endpoints, and it's what a registration-centre operator would use to review what an applicant submitted before processing them.

**Request & response**

No request body — `preRegistrationId` is a path parameter:
```
GET /preregistration/v1/applications/prereg/{preRegistrationId}
```
On success:
```json
{
  "response": {
    "preRegistrationId": "98745627893456",
    "createdBy": "the caller's user ID",
    "createdDateTime": "2026-08-07T10:00:00.000Z",
    "statusCode": "Pending_Appointment",
    "langCode": "eng",
    "demographicDetails": {
      "identity": {
        "fullName": [{ "language": "eng", "value": "Test Applicant" }],
        "dateOfBirth": "1996/01/01",
        "postalCode": "14022",
        "phone": "8249742850",
        "email": "goku@hogwarts.co.in"
      }
    }
  },
  "errors": null
}
```
On failure (ID not found), `errors[0].errorCode` = `PRG_PAM_APP_005`.

**Who can call it**

Only the applicant themselves, or registration-centre staff (an officer, supervisor, admin, or pre-registration admin) acting on the applicant's behalf, may fetch this data. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
