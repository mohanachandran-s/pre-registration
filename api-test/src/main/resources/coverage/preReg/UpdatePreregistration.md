**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Updates the demographic details of an existing pre-registration application — for example, correcting a phone number or date of birth before the applicant's appointment. Unlike creation, this always targets one specific existing record via its `preRegistrationId` in the path, and it only ever touches demographic data: it does **not** change the application's lifecycle status by itself (confirmed by row `TC_prereg_UpdatePreregistration_015` below, whose whole point is that a demographic-only update leaves status untouched) — advancing status is a separate call to `UpdatePreRegStatus`.

**Request & response**

Same MOSIP envelope and the same dynamically-generated, schema-driven request template as `createPrereg` (see that file's automation notes), with one addition: the path also carries `preRegistrationId`, and the generated template includes it as a top-level field alongside the demographic payload.
```json
{
  "id": "mosip.pre-registration.demographic.update",
  "version": "1.0",
  "requesttime": "2026-08-07T10:00:00.000Z",
  "request": {
    "langCode": "eng",
    "demographicDetails": {
      "postalCode": "14022",
      "phone": "8249742850",
      "email": "goku@technoforte.co.in",
      "dateOfBirth": "1996/06/15"
    }
  }
}
```
On success, the response echoes back the updated fields plus when the change happened:
```json
{
  "id": "mosip.pre-registration.demographic.update",
  "version": "1.0",
  "responsetime": "2026-08-07T10:00:01.000Z",
  "response": {
    "preRegistrationId": "98745627893456",
    "updatedDateTime": "2026-08-07T10:00:01.000Z",
    "statusCode": "Pending_Appointment",
    "langCode": "eng"
  },
  "errors": null
}
```

**Who can call it**

Only the applicant themselves, or registration-centre staff (an officer, supervisor, or admin) acting on the applicant's behalf, may update a pre-registration. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
