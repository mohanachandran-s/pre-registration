**What this endpoint does**

Books an appointment slot at a registration centre for a pre-registration application — reserving a specific date and time window so the applicant knows when to physically visit. This is the step that moves an application from "Application Incomplete"/"Pending Appointment" toward "Booked".

**Request & response**

```
POST /preregistration/v1/applications/appointment/{preRegistrationId}
{
  "id": "mosip.pre-registration.booking.book",
  "version": "1.0",
  "requesttime": "2026-08-11T10:00:00.000Z",
  "registration_center_id": "10003",
  "appointment_date": "2026-08-20",
  "time_slot_from": "09:00:00",
  "time_slot_to": "09:15:00"
}
```
On success, the response confirms the booking (no distinct fields are asserted by any current test — every positive case only checks for the absence of `errors`). On failure, `errors[0].errorCode` identifies the problem — see the grid above for the full set of codes this endpoint's validation produces.

**Who can call it**

The applicant themselves, or a registration-centre officer acting on their behalf, may book an appointment. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_

<summary>Technical details (automation + verification notes)</summary>

**Where the role rule lives:** `@PreAuthorize("hasAnyRole(@authorizedRoles.getPostappointmentpregid())")` on `AppointmentController.bookAppoinment`; roles configured via `mosip.role.prereg.postappointmentpregid` = `REGISTRATION_OFFICER, INDIVIDUAL`. Verified against the live controller source.

**The automation discovers a real open slot at run time, rather than hardcoding one.** The wired script class (`BookAppoinment`) calls the live slot-availability endpoint (`GetWithParam`'s sibling GET, configured via the `appointmentavailabilityurl`/`regcentretobookappointment` properties) before every single case, parses a real `(registrationCenterId, date, timeFrom, timeTo)` tuple out of the response, and does a plain string `.replace("$registration_center_id$", ...)` (and the matching `$appointment_date$`/`$time_slot_from$`/`$time_slot_to$` tokens) against the YAML's raw input JSON.
