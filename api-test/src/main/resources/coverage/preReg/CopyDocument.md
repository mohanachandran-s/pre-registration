**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Copies an already-uploaded document of a given category from one pre-registration application to another. In practice this supports a family/household registration flow — a proof-of-address document already uploaded for one member's application can be reused for another member's application without re-uploading the same file.

**Request & response**

No request body — `preRegistrationId` (the destination) is a path parameter, `catCode` and `sourcePreId` are query parameters:
```
PUT /preregistration/v1/documents/{preRegistrationId}?catCode=POA&sourcePreId={sourcePreRegistrationId}
```
On success:
```json
{
  "response": {
    "preRegistrationId": "12345678901234",
    "docId": "98745627893456",
    "docCatCode": "POA",
    "docTypCode": "RNC",
    "docFileFormat": "pdf",
    "refNumber": null
  },
  "errors": null
}
```
On failure, `errors[0].errorCode` identifies the problem — `PRG_CORE_REQ_017` for an invalid/blank category code, `PRG_PAM_APP_005` if either the source or destination `preRegistrationId` doesn't exist, `PRG_PAM_DOC_005` if the category code is valid but no document of that category exists on the source application.

**Who can call it**

Only the applicant themselves (`INDIVIDUAL`) may copy a document — like `uploadDocument`, registration-centre staff are not on this endpoint's role list at all. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
