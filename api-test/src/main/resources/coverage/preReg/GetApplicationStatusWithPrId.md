**About this endpoint**

<!-- ENDPOINT:details -->
**What this endpoint does**

Fetches just the current status code of a pre-registration application — a lighter-weight alternative to fetching the full demographic record when a caller only needs to know where the application stands (e.g. `Application_Incomplete`, `Pending_Appointment`, `Booked`).

**Request & response**

No request body — `preRegistrationId` is a path parameter:
```
GET /preregistration/v1/applications/prereg/status/{preRegistrationId}
```
On success:
```json
{
  "response": {
    "preRegistartionId": "98745627893456",
    "statusCode": "Application_Incomplete"
  },
  "errors": null
}
```
(The response DTO's field really is spelled `preRegistartionId` — a pre-existing typo in the product's `PreRegistartionStatusDTO` class, not an automation error.) On failure (ID not found), `errors[0].errorCode` = `PRG_PAM_APP_005`; on a blank path value, the service returns a raw HTTP 500 with no structured error body.

**Who can call it**

Only the applicant themselves, or registration-centre staff (an officer, supervisor, admin, or pre-registration admin) acting on the applicant's behalf, may check an application's status. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_

<summary>Technical details (automation + verification notes)</summary>

**Where the role rule lives:** `@PreAuthorize("hasAnyRole(@authorizedRoles.getGetapplicationsstatus())")` on `DemographicController.getPreRegApplicationStatus`; roles configured via `mosip.role.prereg.getapplicationsstatus` = `REGISTRATION_OFFICER, INDIVIDUAL, REGISTRATION_SUPERVISOR, REGISTRATION_ADMIN, PRE_REGISTRATION_ADMIN`. Verified against the live controller source.

**This is the read-only status path, not the write path.** `getPreRegApplicationStatus` delegates to `CommonServiceUtil.getApplicationStatus()` — a genuinely different method from `CommonServiceUtil.statusCheck()`, which is what `UpdatePreRegStatus` (a `PUT`) actually mutates through. Confirmed both by reading the source and by this subject's `restMethod: get` YAML field correctly matching the wired `GetWithParam` script class — no `restMethod` mismatch here, unlike the one found in `UpdatePreRegStatus.md`.

**The HTTP 500 on blank ID is a genuine gap, not a placeholder assertion.** `CommonServiceUtil.getApplicationStatus` builds a `requestParamMap` and calls `validationUtil.requstParamValidator(requestParamMap)`, which only rejects `null` values — an empty string passes that check, then fails later (most likely a repository/DB-layer exception) uncaught by any of the service's business-exception handling, surfacing as a raw 500. Verified by tracing `CommonServiceUtil.getApplicationStatus` end to end; no code path there produces a structured `PRG_*` error for this input.
