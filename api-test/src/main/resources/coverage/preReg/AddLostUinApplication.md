**About this endpoint**

**What this endpoint does**

Creates a new application for someone who has lost or forgotten their UIN and needs to visit a registration centre to recover it. Functionally it's the sibling of `AddUpdateRegistration`: both delegate to the same underlying "add application" service method, just tagged with a different booking type (`LOST_FORGOTTEN_UIN` here, `UPDATE_REGISTRATION` there) so downstream steps (appointment booking, registration-centre processing) know which workflow they're handling.

**Request & response**

The request body is deliberately minimal — just a language code, wrapped in the standard envelope:
```json
{
  "id": "preregistration.lostuin.create",
  "version": "1.0",
  "requesttime": "2026-08-07T10:00:00.000Z",
  "langCode": "eng"
}
```
On success, the response confirms the new application and its initial state:
```json
{
  "id": "preregistration.lostuin.create",
  "version": "1.0",
  "responsetime": "2026-08-07T10:00:01.000Z",
  "response": {
    "applicationId": "98745627893456",
    "createdBy": "the caller's user ID",
    "createdDateTime": "2026-08-07T10:00:01.000Z",
    "applicationStatusCode": "SUBMITTED",
    "bookingStatusCode": null,
    "langCode": "eng",
    "bookingType": "LOST_FORGOTTEN_UIN"
  },
  "errors": null
}
```

**Who can call it**

Only the applicant themselves, or registration-centre staff (an officer, supervisor, or admin) acting on the applicant's behalf, may submit a lost-UIN application. Anyone else is rejected with HTTP 403. _(How the login credential itself is transported is the same for every endpoint in this module — see `README.md`'s "How authentication works in this module".)_
